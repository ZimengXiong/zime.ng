    Patching Raycast to Support Longer Pastes
                                                                14 jan 2025


   

   I like Raycast's `Ask AI` mode a lot: you type a question into the
   spotlight search bar followed by `Tab` and your assistant of choice (in
   this case, `Gemini 2.5 Flash Lite`) gives you the answer. However, for
   some reason, there is a max char limit on this field, which is really
   annoying when I am pasting stack traces or code in for a quick answer.
   Raycast's solution to this is to use the full "AI Chat" experience, but
   that ruins the point of the "Quick AI". So onto disassembling and
   patching it is.


   ## Locating the Ask AI UI
   -------------------------

   ### JS??

   My first thought was that the Spotlight "Ask AI" UI might be a web view
   backed by a JS bundle with a front-end `maxlength` or similar
   client-side restriction.

   Raycast ships a web bundle at
   `/Applications/Raycast.app/Contents/Resources/RaycastWeb_RaycastWeb.
   bundle/Contents/Resources/js/index.js`

   The limit might live within a React input prop like `maxLength` or a
   literal string mentioning character limits

   Listing the bundle contents and confirmed that Raycast has both

   - a native Mach-O code at `Contents/MacOS/Raycast`
   - a web bundle at
     `Contents/Resources/RaycastWeb_RaycastWeb.bundle/.../js/index.js`

   Searching the JS bundle for likely indicators found no obvious
   Spotlight/Ask-AI paste limit and no obvious `maxlength` gate tied to the
   root search box:

   .-----------------------------------------------------------------------
   | > rg -n "maxlength|maxLength|character limit|char limit|too long|    \
   |   Ask AI" Contents/Resources/RaycastWeb_RaycastWeb.bundle/Contents/R \
   |   esources/js/index.js
   | <nothing>
   '-----------------------------------------------------------------------

   This meant that the Spotlight input isn't actually a stock AppKit search

   This confirmed that the visible Spotlight input uses the custom text
   field with the paste limit ivar.


   ### Selector and method mapping

   We mapped the `SingleLineTextField` methods using Objective-C metadata

   Method                                                 Location
   -----------------------------------------------------  -------------
   `placeholderAttributedString`                          `0x101f93b78`
   `textDidChange:`                                       `0x101f93cac`
   `textView:shouldChangeTextInRange:replacementString:`  `0x101f921b8`

   The method of interest was `RaycastUI.SingleLineTextField
   textView:shouldChangeTextInRange:replacementString:`, as it forwards
   into a helper that enforces the policy.


   ## Applying the Patch
   ---------------------

   ### Disassembly

   .-----------------------------------------------------------------------
   | > otool -tvV Contents/MacOS/Raycast | sed -n '/101f93cac/,           \
   |   /101f93ea4/p'
   | > otool -tvV Contents/MacOS/Raycast | sed -n '/101f921b8/,           \
   |   /101f922f0/p'
   | 0000000101f93cac        stp     x28, x27, [sp, #-0x60]!
   | 0000000101f93cb0        stp     x26, x25, [sp, #0x10]
   | 0000000101f93cb4        stp     x24, x23, [sp, #0x20]
   | 0000000101f93cb8        stp     x22, x21, [sp, #0x30]
   | 0000000101f93cbc        stp     x20, x19, [sp, #0x40]
   | 0000000101f93cc0        stp     x29, x30, [sp, #0x50]
   | 0000000101f93cc4        add     x29, sp, #0x50
   | 0000000101f93cc8        mov     x25, x5
   | 0000000101f93ccc        mov     x19, x4
   | 0000000101f93cd0        mov     x21, x3
   | 0000000101f93cd4        mov     x24, x2
   | 0000000101f93cd8        mov     x23, x0
   | 0000000101f93cdc        mov     x0, #0x0
   | 0000000101f93ce0        bl      0x1025b5688 ; symbol stub for:       \
   |   _$sScMMa
   | ...truncated
   '-----------------------------------------------------------------------

   There was a critical portion of the helper around `0x101f92220`

   .-----------------------------------------------------------------------
   | 0000000101f92220 ldr x25, [x25]
   | 0000000101f92224 mov x0, x22
   | 0000000101f92228 mov x1, x21
   | 0000000101f9222c bl  _$sSS5countSivg
   | 0000000101f92230 cmp x25, x0
   | 0000000101f92234 b.ge 0x101f9228c
   '-----------------------------------------------------------------------

   where `x25` is the configured `pasteMaxCharactersCount`, `x0` is the
   count of the incoming replacement string. So if `limit >=
   pasted_length`, it would branch to the normal allow path, otherwise,
   fall through to the "too long" path

   Immediately after the failed comparison, the code loads the
   `reachedPasteMaxCharacterCountHandler` closure and invokes it, then
   returns `false`.

   We could've found where the limit was set, and then adjust that, but
   that would've required discovering the runtime value, as well as
   identify every controller that configures the field. Patching the policy
   is much easier.


   ### Calculating the file offset

   I mapped the VM address to a file offset. The patch target had virtual
   address `0x101f92234`. The computed file offset was`0x1f92234`

   .-----------------------------------------------------------------------
   | xxd -g 4 -l 32 -s $((0x1f92230)) Contents/MacOS/Raycast
   |
   | 01f92230: 3f0300eb ca020054 687c00f0 08b947f9
   '-----------------------------------------------------------------------

   Where `ca020054` encodes the conditional branch.


   ### Patching bytes

   I replaced the conditional branch with an unconditional branch to the
   same allow target.

   .-----------------------------------------------------------------------
   | cp Contents/MacOS/Raycast Contents/MacOS/Raycast.bak-paste-limit
   | printf '\x16\x00\x00\x14' | dd of=Contents/MacOS/Raycast bs=1        \
   |   seek=$((0x1f92234)) conv=notrunc
   '-----------------------------------------------------------------------

   With the patched bytes:

   .-----------------------------------------------------------------------
   | 01f92230: 3f0300eb 16000014 687c00f0 08b947f9
   '-----------------------------------------------------------------------


   ## Re-signing and cleanup
   -------------------------

   Because the app bundle was modified, we have to re-sign it with an
   ad-hoc signature:

   .-----------------------------------------------------------------------
   | codesign --force --sign - /Applications/Raycast.app
   '-----------------------------------------------------------------------

   Now we can paste text as long as we want into Raycast!!
